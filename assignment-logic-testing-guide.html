Phase 1 · 12 Epics

Context

Why we're making these changes

💵

Better Margin Decisions

Today the system ranks vendors using rough estimates — not actual quotes. That means the vendor that looks cheapest isn't always cheapest when the real invoice lands.

🆕

Beta Vendors Getting Volume

Our newer "Beta" vendors (formerly called ASAP) are completely excluded from auto-assignment today. This project brings them into the pool where appropriate.

🎛️

Per-Client Routing Controls

Right now there's no easy way to route a specific client differently. After this change, Sales and Ops can configure routing at the Company, TC, or Passenger level.

🔍

Visibility Into Decisions

When a vendor is auto-assigned today, it's hard to know why. A new Audit Trail tab will show every decision the system made — who was considered, and why the winner was chosen.

Projected outcome: ~$144,900 in annual margin improvement from Phase 1 alone — through smarter routing and accurate cost comparisons. This will be validated during testing.

Current State

How assignment works today

The current logic has two main paths — retail and non-retail — but uses rough cost estimates and excludes Beta vendors entirely. Use this as your baseline when comparing to the new flow.

Future State

How assignment will work after Phase 1

The new logic adds a smarter non-retail split (premium vs cost path), brings Beta vendors into the pool, refines retail routing by email domain, and uses real vendor quotes throughout.

Change 1 of 5

Two routing paths — matched to client type

Every non-retail trip now follows one of two assignment strategies, based on how price-sensitive the client is. The dividing line is the client's effective discount — calculated as the higher of their stated discount or the implicit discount their custom rate represents against the standard rack rate.

Premium Path — Margin Optimized

For clients with < 30% discount

The system prioritizes quality vendors first — TC Preferred, then Savoya Preferred — then finds the lowest-cost option within that quality band.


Vendor order: TC Preferred → Savoya Preferred → Best quality/cost balance


Who this is: Most business clients — the ones we want matched with reliable, high-scoring vendors.

Cost Path — Lowest Cost

For clients with ≥ 30% discount

The system skips preferred vendors entirely and finds the lowest-cost eligible vendor, ranked by actual vendor quote.


Vendor order: All eligible vendors, ranked cheapest first. No preference tiers.


Who this is: Price-sensitive accounts. Lower margin, so we optimize for cost to protect the trip.

Override available (Admin & Manager roles only): The routing path can be overridden at the Company, TC, or Passenger level using the new routing control dropdown — replacing the old "Prioritize Low Cost" checkbox. Sales/CSM cannot modify this setting directly.

Change 2 of 5

Real vendor quotes now drive ranking

Previously, the assignment engine compared vendors using a simplified base rate — not the actual quote the vendor would receive. This caused mismatches between which vendor looked cheapest and which actually was cheapest.

After this change, the ranking cost is built from the actual vendor quote, including all the components below.

✓ Base rate

Already included before — no change here.

🆕 Trial discount

Vendors in trial mode get a configurable discount applied during ranking — so trial vendors compete fairly on actual cost.

🆕 Fuel surcharge

Each vendor's fuel surcharge is now factored into ranking, not just the final invoice.

🆕 Garage travel time

Time billed for the vendor driving to and from their garage is now included in the ranking cost.

Why does this matter for testing?

After this change, the vendor selected by auto-assign may be different than what the old logic would have picked — even for the same trip.

The "right" vendor is now the one with the lowest total real cost, not the lowest base rate.

During testing, compare the selected vendor's full quote against alternatives in the Reassign modal — the winner should genuinely be cheapest on the Cost Path.

Custom rate clients Updated

Clients on custom pricing (not standard rack rates) are now evaluated differently. The system calculates what effective discount their custom rate represents and uses the higher of that or their explicit discount to determine which path they follow.

Change 3 of 5

Beta vendors enter auto-assignment New vendor types

Vendors previously labeled "ASAP Garage" are being renamed to Beta Garage. A new type, Beta I/O, is also being introduced. These vendors now participate in auto-assignment — a major change from today.

Beta Garage

Renamed from "ASAP Garage." Behaves identically to a standard Garage in scoring, robocalling, and communications. Only difference: assignment eligibility is now toggled per client.

Beta I/O

New vendor type. Behaves like a standard Independent Operator (I/O). Same scoring, same communications. Eligibility controlled by the same per-client toggle.

Per-client toggle (Beta Eligibility): Whether Beta vendors appear in auto-assignment is controlled at the Company, TC, and Passenger level. Default is ON for all new clients. Admin/Manager roles only can change this.

What you'll see in testing

  • › Beta vendors appearing in the "Available for Auto-assignment" bucket in the Reassign modal
  • › If Beta is disabled for a client, these vendors appear in "Available (No Auto-assignment)" with reason: "Beta vendor not enabled for this client"
  • › Beta vendors competing on cost or margin alongside standard vendors — no separate bucket
  • › The old "ASAP" bucket in the Reassign modal is removed

Note for Vendor Ops (Dan): Existing ASAP Garage vendors are being renamed automatically. No vendor re-enrollment needed. Their scoring, communications, and robocall behavior stay the same.

Change 4 of 5

Retail trips now route smarter

Retail clients (those who booked through the consumer portal) are treated differently based on their email domain and how many trips they've taken.

🏢

Business email · First 3 trips

Clients who signed up with a corporate email (not Gmail, Yahoo, etc.) get premium routing for their first 3 trips — margin-optimized, to capture value from potentially high-value business accounts.


Preferred vendors: Excluded. Vendor pool: All eligible by cost.

📈

Business email · 4th trip onward

After the trial window closes (3+ completed trips on file), business-email retail clients move permanently to cost-based routing — same as personal email clients.


Preferred vendors: Excluded. Beta vendors: Controlled by toggle.

📧

Personal email · All trips

Clients with Gmail, Yahoo, iCloud, Outlook, and other personal email domains always route cost-based. No trial window. No preferred vendors in the pool.


Always cost-based from trip 1. No exceptions.

Conversion rule: If a retail TC is later linked to a Company (converted to non-retail), all new trips from that point follow the standard non-retail logic. Trips already booked before conversion are unaffected.

Change 5 of 5

Vendors without pricing are excluded from auto-assign

Today, a vendor with no cost on file can still win auto-assignment — they just appear at the end of the list. This leads to assignments where we don't know what the trip will cost until after it's confirmed.

After this change, any vendor without pricing data on file is completely excluded from auto-assignment — on both the premium path and the cost path.

What happens to these vendors?

They don't disappear — they show up in the Reassign modal under "Available (No Auto-assignment)" with the reason: No cost on file.

Ops can still manually assign them from there if needed — the system just won't auto-assign them.

⚠ Important for testing: In some markets, removing costless vendors may shrink the eligible pool. If a service area has very few vendors with pricing on file, you may see more manual-assign fallbacks. Flag this immediately if you see it — we need to track it per market before go-live.

Also excluded from the Cost Path

Preferred vendors (both Savoya Preferred and Client Preferred) are excluded when a trip routes through the Cost Path. This is intentional — on the cost path we're optimizing for lowest price, not preference.

These vendors also appear in "Available (No Auto-assignment)" in the modal with reason: Preferred — skipped.

Busy garages also excluded

Garages where all drivers AND all vehicles are already confirmed on other trips within 2 hours of pickup/dropoff will be excluded from auto-assignment.

UI Change 1 of 2

Redesigned Reassign Vendor Modal

The biggest day-to-day UI change for ops. The modal now has four clear buckets, more vendor detail, and explicit reasons for every exclusion.

✓ Available for Auto-assignment

Vendors the system would actually send this trip to, listed in the exact order they'd be offered. Includes vendors whose offer was declined or expired — they stay here with their offer status shown.

⚠ Available — No Auto-assignment

Vendors that could serve this trip but are being deliberately skipped by new Phase 1 rules. Each one shows a reason:
"No cost on file" · "Beta vendor not enabled for this client" · "Preferred — skipped"
Ops can still manually assign from here.

📉 Low Margin

Same as today — vendors that exceed the 90% margin ceiling. No change to this bucket.

🚫 Unavailable

Vendors that fail a genuine filter — vehicle type mismatch, blackout, conflicting trip, vaccination requirements, etc. Now expanded to show all active vendors in the service area, with a plain-English reason for each exclusion.

New columns in the modal

💰 Vendor Quote 📊 Score 🔵 Algo Cost 🔢 Scoring Detail ⭐ Preference (SV / CP) 📝 Decline Reason ✕ Exclusion Reason 🔗 Vendor Profile Link
Note: The old "ASAP" bucket is gone. Beta vendors are now part of the main assignment pool. The "Decline Reason" column (Offer Sent / Declined / Expired) is separate from the "Reason" column (why a vendor is excluded) — these mean different things.

UI Change 2 of 2

New: Vendor Assignment Trail

A new tab on the reservation page — "VENDOR ASSIGNMENT TRAIL" — that logs every decision the system made for each assignment event. Visible to Admin and Manager roles only.

👤

Client Section

Shows: TC name, Retail or Non-Retail status, discount level applied, and which routing path (premium or cost) was used for this trip.

🔽

Filter Funnel

Step-by-step view of how the vendor pool was narrowed — how many vendors passed each filter stage and which specific vendors were removed at each step.

📋

Eligible Vendors

Full ranked list of vendors that made it through all filters — with their score, cost used for ranking, and actual quote. The winning vendor is highlighted.

🧭

Decision Path

Bullet list of each logic decision: which path was taken, whether preferred vendors were matched, and what triggered the routing choice.

💲

Client Quote

The client-facing quote at assignment time — base rate, discount, margin threshold, and adjusted total.

🏁

Result

The final outcome: which vendor was assigned, their score, and the cost that drove the decision.

Each assignment and reassignment creates a separate entry in the trail, so you can see the full history of a reservation's vendor decisions in one place.

Safety Net

Every change is behind a feature flag

None of these changes are all-or-nothing. Each piece of logic is controlled by a feature flag — a toggle that can be turned on or off per client, per market, or globally — without a code deployment.

Cost vs. Premium Routing Override

The 3-option dropdown (Premium / Cost / Default) at Company/TC/Passenger is independently configurable. If a specific account needs to be locked to one path, this can be set without affecting other accounts.

Beta Vendor Eligibility

Beta vendors can be toggled off per Company/TC/Passenger. If a client shouldn't see Beta vendors, flip the switch. Default is ON for all new clients.

Real Quote Ranking

The switch from estimated rates to real quotes in cost ranking is behind a flag. If we see unexpected behavior in a market, we can roll back to the old behavior for that subset while investigating.

Retail First-3-Trip Window

The logic that gives business-email retail clients margin-optimized routing for their first 3 trips is controlled separately and can be toggled without affecting corporate clients.

Launch defaults: At go-live, all routing overrides are set to "Default" (discount-based logic applies for everyone). No accounts will be forced onto a new path immediately — behavior changes gradually as the system uses real quotes. This gives us a clean baseline to measure from.
