Transportation Grouping Feature

Client Manifest → AI Conversion → Review → Grouping → Views → Reservations

Step 1
Client Manifest
Client uploads their manifest in any format — CSV, Excel, PDF, or however they receive it from their aviation department. Contains flight details, traveler info, and travel legs.
Step 2
AI Agent
AI-Powered Conversion
An AI agent reads the uploaded file — regardless of format or column naming — maps the data to our schema, and converts it into a standardized manifest the system understands. This is the hardest part.
Step 3
Review & Correct Converted Data
System shows the user what the AI converted. User can review, edit, and fix any data the conversion didn't catch correctly before proceeding. Three tabs: Arrivals, Departures, Transfers.
Step 4
Grouping Logic
System groups travelers based on selected strategy. "Recommended" is a Savoya-predefined strategy for the client. Additional strategies to be defined.

Step 5
Views + Manual Adjustment + Quote
Three views of the grouped data — Passenger, Manifest, Trip — across all 3 legs (Arrivals, Departures, Transfers). Users can manually adjust groupings (e.g. move a traveler to a different car). Quote auto-updates as groupings change.
Step 6
Conditional
Change History
Appears when you re-upload or edit a source file after reservations exist. Shows summary of changes, cost delta, and lets admin accept or reject.
Step 7
List of Reservations
Final confirmed reservations — all three legs (Arrivals, Departures, Transfers) with vehicle assignments, pickup times, passenger lists.

Scope

Key deliverables for the transportation grouping feature.

1
Conversion Tool (AI Agent)
AI-powered ingestion that accepts any file format (CSV, Excel, PDF) from client aviation departments. Maps arbitrary column layouts to our schema. The hardest part of the project.
2
Grouping Logic → Template
Implement the grouping algorithm with "Recommended" (Savoya preset) plus additional strategy categories (TBD). Define the generic data structure.
3
Data Schema & Data Models
Database schema for manifests, traveler records (3 leg types), groups, vehicles, reservations, change history.
4
Microservices
Backend services — AI conversion service, grouping engine, reservation service, notification service.
5
Views, Delta & Components
Build the three views (Passenger, Manifest, Trip) across all 3 legs, manual adjustment (drag to regroup), live quote component, and the data review/correction screen.
6
Change History
Track re-uploads and edits — show what changed across all legs, cost delta, accept/reject workflow.

Open Questions & Decision Points

AI conversion accuracy: What's the fallback if the AI agent can't map a column? Show it as "unmapped" and let the user assign it manually?
Manifest tab structure: Arrivals and departures come as separate tabs in client files. Transfers are a third tab the client adds. What if there's no transfer tab — do we prompt for it?
Grouping time window (± x mins): What's the default for the "Recommended" strategy? Is it per-client configurable?
Destination proximity (± y miles): Radius-based, zone-based, or exact match? Different per leg type?
Additional grouping categories: What are categories 2 and 3 beyond "Recommended" and "Custom"? Pricing-focused? Comfort-focused?
Manual adjustment UX: How does drag-to-regroup work? Drag a traveler card into a different vehicle group? What constraints prevent bad groupings?
VIP handling: Always separate vehicles? Or just priority seating? How is VIP flagged — in the CSV or configured per client?
Quote calculation source: Where do vehicle prices come from? Static rate card, vendor API, or admin-configured per client?
Transfer leg grouping: Do transfers use the same criteria as arrivals/departures? Or grouped primarily by event/destination?
Re-upload behavior: When re-uploading after reservations exist, auto-update or require admin review of the change delta?
Departure grouping: Same rules as arrivals or different logic? Departures may have less flexibility on timing.
